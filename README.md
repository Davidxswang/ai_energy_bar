# ai_energy_bar

Surfaces local usage signals for Claude Code, Codex CLI, and Gemini CLI in your
desktop's top bar:

- **Ubuntu 24.04 / GNOME Shell 46** — native shell extension (`extension/`).
- **macOS** — menu bar app via `rumps`/`NSStatusItem` (`macos/`).

Both front-ends share one local probe (`extension/probe.py`); only the UI layer
differs per platform.

## Current v1 behavior

- Codex: live quota probe from the latest local session JSONL rate-limit events.
- Claude Code: live quota probe by launching the official CLI and parsing the `/status` usage view.
- Gemini CLI: live quota probe from the installed official Gemini CLI quota path, matching the data surfaced by `/stats`.

The extension avoids private hosted APIs. Exact remaining quota is currently available for Codex, Claude, and Gemini using local session state or official CLI-backed quota data.

## Layout

- `extension/metadata.json`: GNOME Shell extension manifest
- `extension/extension.js`: GNOME top-bar widget and dropdown UI
- `extension/probe.py`: local status collector (shared by both front-ends)
- `extension/stylesheet.css`: extension styles
- `macos/app.py`: macOS menu bar app (rumps glue, macOS-only)
- `macos/render.py`: shared, cross-platform presentation logic
- `scripts/install-dev.sh`: local install script (GNOME)

## Install for local development

```bash
./scripts/install-dev.sh
```

Then log out and back in on Wayland if GNOME does not reload the extension automatically.

## Uninstall

```bash
./scripts/uninstall-dev.sh
```

## macOS menu bar app

The macOS front-end reuses the same probe and renders it in the menu bar.

```bash
uv sync --extra macos          # installs rumps (macOS only)
uv run python -m macos.app     # run from the repo root
```

The menu bar shows an **icon** (a template "levels" glyph that tints itself for
light/dark menu bars); all quota values live in the dropdown. It polls every 15
minutes (matching the GNOME extension), runs the probe in a worker thread with a
timeout so a slow Claude probe never freezes the bar, and offers a "Refresh Now"
item. A probe failure shows a `!` badge beside the icon. The `macos` extra is a
no-op on Linux, so the rest of the dev workflow is unaffected there.

The icon (`macos/icon.png`) is generated by a dependency-free script; regenerate
or tweak it with `uv run python macos/make_icon.py`.

> Not yet exercised on macOS hardware — the cross-platform rendering core
> (`macos/render.py`) is unit-tested and the icon is a validated PNG, but the
> rumps UI glue (`macos/app.py`) still needs a run on a Mac to confirm the icon
> and dropdown render as intended.

## Probe manually

```bash
python3 extension/probe.py --pretty
```

## Development setup

```bash
uv sync --group dev
uv run python extension/probe.py --pretty
uv run ty check
```

When installed via `./scripts/install-dev.sh`, the GNOME extension prefers the repo-local `.venv` interpreter at `<repo>/.venv/bin/python3` and falls back to system `python3` if that environment is unavailable.
